# 共享卡面原生还原与验收记录

本轮基线为 develop `d2e0baa3`，仅修改共享卡面装配、卡面显示绑定和对应工程门禁。规则数据、地图与主菜单不在改动范围。

验收以五类入口都使用同一组件、148×208不变、费用及文字仍由原数据/核心计算、原生装配可读回为准。原生实机验收由用户自行导入；本记录不将离线预览算作实机通过。

## v2.0.0 卡牌正文排版

原版简繁中文接受作者指定的换行，并按测得字宽自动换行。字典识别的词、动态数值标记和能量图标各自是排版单位。普通中文可以在字间换行，孤立句号并回上一行。普通卡面保持 5:7 比例，默认正文换行宽度为卡宽的 72%，全局大字模式为 87%。普通源码逻辑字号为 24，行距约为字形顶高的 1.45 倍。 [语言设置](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/core/Settings.java#L381-L435) · [中文排版与关键词](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/cards/AbstractCard.java#L486-L650) · [正文绘制](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/cards/AbstractCard.java#L1689-L1772)

超过五行只触发原版开发日志。单卡查看由玩家主动打开，以居中大卡重画同一正文行，使用 48 号字体和约 1.53 倍字形顶高的行距。原版在这条路径上也一次绘制全文。长描述的完美打击、腐化及升级武装在实际游戏画面上都采用同一卡面阅读。 [单卡绘制](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/screens/SingleCardViewPopup.java#L687-L735) · [官方预告手牌抬升](https://playcraft.space/gallery/slay-the-spire/combat-card-inspection-hand/) · [原版奖励选牌](https://interfaceingame.com/screenshots/slay-the-spire-choose-a-card/) · [完美打击实战](https://waytoomany.games/2019/05/20/review-slay-the-spire/) · [腐化实战](https://indiegameculture.com/slay-the-spire-getting-started/) · [升级武装实战](https://www.hermitgamer.com/slay-the-spire-ironclad-guide/)

本项目按以下顺序处理长度问题。

1. 先编辑现有卡牌文案。保留效果对象、数量、触发顺序、时点、条件和例外。删除重复标明的一次性状态移除等实现细节。
2. 对已登记的先天、虚无、消耗和具名状态，正文保留实际施加的状态、数量及影响，复用字典定义解释术语。没有关键词入口的商店和选牌场景也要能从普通卡面读出关键规则。关键词随着正文投影检出，重复词只展示一次。卡牌没有可解释术语时只显示卡面。
3. 普通卡面共用 `CardDisplay` 正文测量与写入。正文沿用原生换行，测量保留数字及拉丁串、中文开闭标点和原有颜色标记。字号下限为全局 14，垂直预算采用统一 1.3 倍行高。正式卡面从 120×76 起，按全局档位扩展到 128×96、128×116 或 128×132，保持正文底锚和卡面比例。默认表面沿用同一适配器和主题尺寸。任何牌新增或改写文案都必须用相同的共享预算审核。
4. 仍超出普通卡面容量时，读取现有居中单卡。普通面使用「查看卡牌」作为入口提示，点按原有牌堆卡片、桌面悬停后右键，或移动端有效长按释放，读取同一个 `cardFocus` 卡面。单卡在放大后的可用尺寸内以固定下限重新测量，使用相同印刷或战斗正文。商店和强制选牌入口按常规卡面审核容量。若可查看入口的大卡也无法适配，该文案必须回到第 1 步调整后才纳入发版。查看、取消和关闭分别校验各自的触点序列。

全目录审计覆盖生产 Run 的 368 个定义，包括棱镜碎片可取得的 320 张牌及基础牌、状态、诅咒和临时生成牌。每个定义检查基础与升级版的印刷、普通战斗、高数值及虚弱／脆弱战斗正文。用正式和默认生成卡面分别验证手牌、牌堆、奖励、选择、商店和大卡，保留数值结算、费用、升级标记、颜色和触点定向回归。离线尺寸审核使用原生控件模型，官方客户端字形裁切和实体触点须另行验收。 [目录审计](../../tests/lua/card_body_catalog.lua) · [超限与触点回归](../../tests/lua/card_body_focus.lua)

## 原生能力与差异

能力依据：本机MCP `src/scene/image-library/index.json` 的shape分类及 `shape_00.jpg`（2026-10-13采集），实查100001矩形、100002圆片、100003三角、100004四芒星、100006圆环。`docs/TOOLCHAIN.md`指定的MCP工作流和平台规则经离线读取；候选构建另保存原资源返回。只写副本，`MILIASTRA_ALLOW_LIVE_WRITE=0`。

一张战斗卡共119个控件（含容器），单容器最多29子控件，小于60门槛；并不代表多卡性能已经实测。装饰按角色/类型/稀有度/状态缓存，卡槽变化后重新绑定；弱键缓存不持有被销毁的原生控件。

原稿Card的296×416视图按1/2比较。原生外框保持148×208；沿用现有40费用圆、64高插画窗和132×92正文，原稿相应为30费用圆、79高插画窗。原因是原生中文最低14px与全文预算，不能把原稿2倍预览中的8–13px文字直接导入。该比例差异公开保留，未声称像素一致；未来如改窗高须同步重验全部长文卡。

CSS径向辉光、金属反射及SVG路径没有直接导入。标题使用八层原生图片色阶，费用反馈使用原生圆环缩放，徽记使用图库图形装配。类型图标沿用既有原生占位；下方SVG中的菱形只是预览标记。正式类型图标与发光强度须在游戏中核对。

## 用户导入检查

测试候选路径、hash与构建读回结果在本文件后续候选段记录。导入后分别检查：战斗不同类型/费用变化/不可打出、牌库长文与升级卡、奖励三张卡、商店七卡与买不起状态、锻造前后费用降低与确认结果。观察圆角接缝、角色徽记、尖底/拱顶、全文和类型标签，记录截图及本轮日志。检查1/5/10手牌时流畅度。

本轮不占用用户键鼠、不导入官方客户端；`verify:ui`需要候选hash对应的本轮实机截图和批准项，因此未宣称UI验收通过。平台性能、手机实屏及原生图形接缝仍待用户试玩证据。
