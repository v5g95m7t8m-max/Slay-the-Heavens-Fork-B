# 2.0.0 修复：战斗敌人错图与缺少可辨识画像

正式音频候选默认是 cards=false、menuBackground=true、selectionAvatar=true、battlePortrait=true、monsters=false，不是官方素材试玩配置。旧正式路径给两幕 42 个敌人绑定 26 个图库图标，其中 28 个敌人身处 12 组共享图标；例如赤／青甲虫被画成岩史莱姆、石颚兽被画成野猪。此前已审阅的 42 张可辨识简图在正式默认未接线。

本修复只给标准发行配置的战斗 Actor 增加敌人简图池；不启用旧 600 槽图库，不带入试玩配置、药水、遗物、卡牌、菜单或玩法变化。正式默认 42 个敌人各有独立图形，包含两幕 Boss、召唤单位和史莱姆分裂体；未知 ID 和写入失败保留旧路径回退。

- 复用已有 42 项基础库，四个已审阅的史莱姆形象则用归档中的正式选稿：小酸 32 图元、中酸 41、小棘刺双眼 41、中棘刺 41。来源提交、路径和 SHA-256 与素材逐项绑定在 `data/presentation/release-enemy-art.json`。未重画已接受的其他源稿。
- 每只预留 41 个图元控件、1 个图层容器，Actor 控件总数从 35 到 77（不含状态控件）；5 只同时预留 210 个新增绘图控件（包括 5 个容器）。可见计数按资产，不等于设备性能。待机不改原姿态实现。
- 其余 38 个 ID 复用上次审阅的轻量简图，不宣称这些都是最新原神参照精修版。已批准的 119 控件遗迹守卫精修保留在归档；本修复用已有可辨识简图替代错用图库的外形，不为一个敌人把所有人的池提升到 115，也没有启用新的引擎池机制。
- `node --test tests/native-enemy-portraits.test.mjs` 走真实构建配置与生产 GameUI/Combat 的离线模拟，检查 42 项及召唤、分裂共 56 次绘制；断言使用正确图元、颜色、XYZ、控件占位与隐藏错误图库头像。无真机、官方导入、官方容量或帧率结论。

生成物的同配置对照：UI 主布局与旧原生怪物模块字节不变；编译主题增加 114,688 字节，Actor 所在模板 JSON 增加 11,834 字节。这是生成物，不是压缩 GIL 或平台容量。
